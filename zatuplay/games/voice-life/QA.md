# Voice Life normal-UI acceptance recipe

## Historical implementation-task scope

This paragraph is retained as the historical implementation-task record, not a statement that subsequent coordinator checks never happened.

**Not run by the implementation task:** actual browser/HTTPS/public launch, file chooser/download, two actual tabs, actual microphone/audio hardware, actual midnight observation, phone/tablet, Safari/Firefox, offline refresh. Model tests are not substitutes for these checks. Do not request/accept microphone permission unless the owner has explicitly authorized that current challenge; no such permission was requested during implementation.

## Chrome, without microphone

1. Serve the checked repository root through the existing local QA server, or use a staged public HTTPS entry after authorized deployment. Open `zatuplay/games/voice-life/` by ordinary navigation. Confirm version `7.0-web.1`, fictional/local/no-audio-recognition/no-paid-coins notices, no console errors and no remote asset/network requests. Direct return must go to `../../browser/` in the same tab. A not-yet-published catalog must not advertise this build as verified.
2. Use a clearly fictional profile, e.g. `架空のテスト放送局`, never a real private name, age, birthday, location or picture. Register. Open all five main tabs and CPU visit view. Verify standard **マイクなし** mode is selected. Start LIVE using its normal button, wait for genuine 1.7-second CPU simulation ticks until listeners and interactions occur, type a short fictional comment, click normal and ×10 like buttons. Observe CPU text, gift (random), viewer/like/gift counts and rank. Stop normally. Compare final points/history/follower counts, reload and verify retained state. Do not force model state or speed up time and call it ordinary gameplay.
3. Start/stop repeatedly; switch main tab/room, change mode without starting mic, navigate back/forward, hide the browser and return, reload. These must terminate/settle a running stream once, never keep adding points while hidden, never carry an older reply into a new stream, and never leave a microphone-pending state. A currently empty room/gift absence is randomness, not evidence that gifts were verified.
4. Visit multiple CPU rooms, send text/likes/follow, leave and revisit rapidly. Search listeners and hosts, open/close CPU profiles by button, backdrop and Escape. Two hosts whose displayed names match should have separate `h:` follow IDs internally but the user-facing name must remain original. Check following/unfollowing through CPU profile buttons. Never imply real people were contacted.
5. Create a fictional custom family, check seven CPU members and contribution; send several local family messages, leave with both Cancel and Confirm, join each suggested family. Start a no-mic stream, cancel cohost prompt, then invite a valid first-12 choice, try repeated invite, end cohost and stream. Check +25 initial cohost session points and no duplicate end settlement.
6. Open ranks/events/gift catalogue/lifestyle schedule. Verify seven rank bands and eight gift tiers in UI. Today's board is provisional. Daily reward descriptions must say **last observed JST rank**, not exact midnight history. A model fixture can test all reward/time boundaries but must be labeled as such; two-day real observation is a separate optional check. With no pending rewards, clicking claim should not change wallet.
7. Edit all profile fields using fictional data. Try invalid handle and `javascript:` link, then valid handle and `https://example.test/fiction`. Validate cancel/reset fields and display-only visibility labels. Browse away and back with an unsaved edit: source behavior is retained, drafts are not automatically persisted. Save valid edits and reload.
8. Choose a small non-private JPEG, PNG and WebP via real chooser. Verify avatar/banner aspect-preserving downsizing. Cancel chooser; choose same file again; quickly choose/clear/change, navigate away, reset or import while processing. Late work must not reapply old media. Reject SVG/wrong MIME/over-15-MiB and extreme-dimension files. Verify no external image request, then reload persisted images. Do not use personal photographs for QA.
9. Export normal JSON with the real Download button, verify downloaded filename/content, change a profile value, import that actual downloaded file through the real chooser, Cancel once and Confirm once, then reselect the same file. Reject malformed/unknown-field/truncated/oversized backups. Start import while navigating or changing a saved value; stale read must not overwrite newer work. Reset with Cancel then Confirm, use **置換前に戻す**, export previous/original raw copies, and check image/profile restoration and reload.
10. Open the same entry in a second real tab. It must report memory-only and never overwrite the writer. Change state in each, refresh the reader to see durable writer data. Close writer and reload the desired tab to take ownership. Test recoverable quota/denied-storage fixtures using browser-supported settings or a separate disposable test origin, not by deleting real user data. Original four native keys must remain unchanged. Test a deliberately corrupted isolated save only in disposable QA storage and verify no automatic overwrite; Retry must refuse, confirmed reset must retain original raw bytes for export.
11. At ~375 px width inspect headings, toolbar, nav wrapping, profile fields, media controls, chat, family, modal and return link. Check keyboard focus/Enter/Escape and reduced motion. Device emulation is not actual mobile-device verification.
12. Record URL, exact version/commit, UTC time, browser/platform, observations and which checks passed/failed/not-run. Recheck after fixes. Keep local-model evidence distinct from real UI and public HTTPS availability.

## Optional microphone acceptance, only after owner permission

Use a real input device on HTTPS/localhost. Select mic explicitly and start. Cover denied permission, unavailable device, pending permission then Cancel/changed mode/navigation/pagehide/reset, late grant after cancel, repeated starts, track-ended events and browser back/forward. Verify all tracks end on every exit and no audio leaves the page. No recording/playback/speech recognition is implemented, so there is no voice-recognition or audio-output success claim. A mocked MediaStream passing tests does not establish hardware behavior.

## Coordinator public Chrome QA: current recovery run

On 2026-11-12 around 10:02–10:04 UTC, a newly clean Chrome loaded public HTTPS version 7.0-web.1 normally. A fictitious local profile (`架空の復旧確認`) was registered. Default no-microphone LIVE, ×10 likes, normal CPU participation/comments/gifts, and explicit stream end were exercised. End returned OFF AIR with 33 rank points. Reload retained the synthetic name and 136 likes / 2 gifts / 6 gift coins / 1 stream / 1 minute / 33 points. No microphone permission was triggered. This is a new limited smoke test, not a recreation of the older three-stream state.
