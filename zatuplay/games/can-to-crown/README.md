# Can to Crown ブラウザ版

元作品: `05.Can-to-Crown-v2.1.apk` / `jp.sakihana.cantycoon`
ブラウザ版: `2.1-web.1`
状態: ローカル自動検証済み。公開ブラウザでの通常操作検証とカタログ登録は未実施。

## 保持した原作

これは缶拾い経営ゲームのブラウザ移植です。別の小規模ゲームへの置き換えではありません。原作はAndroidネイティブJava/Canvasで、HTML、画像、音楽ファイルはありません。元の400×800配置、図形、配色、全ての経営・交流要素をCanvas 2Dへ移しました。ブラウザやOSによる字体の違いがあります。

- 20個の缶。普通・きれい・お宝の3種。原作の確率は金8%、金以外の22%が緑、それ以外が普通です。
- 5地区: 川沿い、駅前、商店街、イベント広場、港の街。累計収入0 / 1,000 / 12,000 / 120,000 / 1,000,000円で解放。缶を持っている間は移動できません。
- 道具15段階、袋20段階、売却ボーナス15段階、住まい4段階。袋は20＋容量段階×30個。売却価格は地区単価×缶数×（1＋売却段階×0.2）。
- 6段階の事業。購入額500 / 4,000 / 35,000 / 300,000 / 2,500,000 / 20,000,000円、毎秒収入8 / 75 / 700 / 6,500 / 60,000 / 550,000円。評判1につき1%加算、最大100%。
- 20イベント、20街人と台詞、20依頼、20収集品、20実績。図鑑は100項目。文言・順序・条件・報酬は元DEXから取得しています。
- 依頼の回収・売却・収入は受注後の差分。道具・事業・住まいは現在の段階。完了報告、報酬の一度限りの受取、中止・再受注を保持。
- 25回の回収または60秒の活動で順番にイベント。参加と休憩、時間制2倍効果、評判報酬を保持。メニュー表示中は新しいイベントを開始しません。
- 目標は**累計収入でなく所持金1億円**。エンディング、クリア後の継続、再鑑賞、やり直しを保持。
- 効果音ON/OFF。元APKのAndroid ToneGeneratorに代わり、ブラウザの65ms合成通知音を使用。原音と同一波形ではありません。音楽は元APKにありません。

追加の有料サービス、実際のお金による取引、外部広告、外部素材・画像・音楽はありません。

## 操作・保存

缶やボタンをクリック／タップ。TabとEnter/Spaceでも操作できます。矢印キーで缶を選択、Sで売却、1〜5で下部メニュー、P/Escapeで一時停止。

操作ごとと約4秒ごとにブラウザへ保存します。元の保存項目に加え、現在の画面、20個の缶の種類、選択待ちのイベントと報酬も保持します。再読込は「つづきから」、画面移動・非表示・大きなフレーム停止は「再開する」を押すまで止まります。

**時計の区別:** 原作と同じく事業収入と60秒イベントは活動時間です。閉じている間の収入はありません。売価・回収・事業の2倍効果は保存された実時刻で終了するため、一時停止・ページを閉じている間にも60秒の期限が経過します。

「保存」からJSONを書き出し／読み込みできます。読み込みは形式と数値を検証し、画面での確認後に復元します。やり直し／復元前の保存はそれぞれ予備データとして同じブラウザに残します。キャンセル・不正ファイルで元データを変更しません。同じファイルの再選択にも対応。

Web Locks対応ブラウザでは、この作品のプレイ用ロックを保持し同時書込を防止します。非対応環境では元の保存を上書きしない一時プレイとし、進行を保存しません。注意を常時表示し、今回の進行はJSONに書き出せます。復元による保存も行いません。保存破損・書込拒否・容量不足・競合は停止して知らせ、古いタブから上書きしません。停止画面から現在の進行／元の保存を書き出せます。

保存はブラウザ・オリジンごとです。APKや別端末とは自動同期しません。ストレージ削除、プライベートモード終了、保存前の強制終了では進行を失う場合があります。起動には通信が必要で、オフラインキャッシュは追加していません。

## 原本・復元根拠

- `reference/classes.dex`: 元APKからバイト変更せず保全した実行コード。
- `reference/original-data.json`: DEX命令から直接抽出した12×20＝240個の拡張データ値と8個の基本テーブル。
- `original-source.json`: APK・DEX・非署名のAPK構成ファイルのサイズとSHA-256、データの一致記録。
- `PORTING_NOTES.md`: 数式・原メソッド対応とブラウザ向けの差分。

文字列配列を欠落させるJava逆コンパイル表示は採用していません。const-string、filled-new-array/range、aput、fill-array-dataを元DEX上で評価して配列を復元しています。ゲームデータのJSONは起動時に形式検査を行い、対応するブラウザではSHA-256も検証します。

## 自動検証の再実行

プロジェクトの共有package/lockは変更していません。検証用に `linkedom` と `@napi-rs/canvas` を利用できるNode環境を用意し、`zatuplay-source` で以下を実行します。

```
node scripts/test-can-to-crown.cjs
sha256sum -c scripts/can-to-crown-files.sha256
npm run check
```

DEXから再抽出する場合はPythonとandroguard 4.xを用意します。

```
python scripts/extract-can-to-crown.py public/games/can-to-crown/reference/classes.dex extracted-can-to-crown.json
cmp extracted-can-to-crown.json public/games/can-to-crown/reference/original-data.json
```

自動検証20群: 原本・全テーブル・ミラー、全強化／5地区／20街人／20依頼／20イベント／20実績、通常ルールを用いた経営から1億円ED、保存再読込、入力、停止、全100図鑑、やり直し、複数タブ、保存異常、通信・データ異常、JSON復元、音声APIの呼出しを確認。Canvas2Dで各画面を描画し、日本語を含む画像を検査しています。

ロジック試験には条件境界の固定状態を使用しています。通常ルールの完走試験は多数の高速テスト入力と模擬時計を使用し、通貨の直接注入はしていません。いずれも実ブラウザでの手動攻略ではありません。DOM、時刻、Web Locks、音声APIはテストモデルです。

## 公開前の通常ブラウザQA

1. 一覧から起動、開始、20個の缶と5メニュー、クリック／キー操作を確認。
2. 「街人」→「街人に話しかける」→「清掃員・まこと」→依頼受注。初回交流の120円と評判＋1。
3. 缶を25個以上拾う。袋は20個で満杯なので途中で売却。「街人」→依頼→報告。報酬300円、評判＋2、依頼記録を確認。
4. 実績「はじめの一缶」の報酬200円を受け取る。同じ報酬を二度受け取れないことを確認。
5. 500円で「回収の手伝い」を購入し、自動収入。累計1,000円後、缶を売って駅前へ移動。再読込して資金・袋・強化・依頼・図鑑・現在地・音設定を確認。
6. 25タップのイベント参加／休憩、選択待ちの再読込、図鑑の分類・項目・戻る、一時停止→明示再開、別タブへ移動→復帰を確認。
7. 保存JSONを実ダウンロード、復元キャンセル、同じファイルで復元、再読込。やり直しの取消、複数タブで古い進行が上書きしないことを確認。
8. 全5地区・1億円EDまでの手動完走は別途確認。自動検証の完走と混同しないでください。
9. 上部リンクからZatuPlay一覧へ戻れること、ゲーム由来のコンソールエラーがないことを確認。
