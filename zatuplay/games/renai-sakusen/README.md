# 恋愛作戦実行中 ブラウザ版

- 原作 Android 0.2.0 / ブラウザ版 **0.2.0-web.1** / collection-29
- 原作者の完成済みAPK内のWeb作品を移植。代替の物語や人物は作っていません。
- `story.js`、`expansion.js`、6枚の人物PNGは原本とバイト単位で同一です。原作11ファイルのサイズ・SHA-256、APK全体のサイズ・SHA-256、移植範囲は `provenance.json` に記録しています。APK本体、Androidラッパー、署名、非公開の転送情報は含みません。
- 配布ファイルのハッシュは `checksums.sha256`。元ソース側と公開側の同名ディレクトリは完全同一です。

## 原作の内容とルール

24人（男性12人・女性12人）、主人公2人。初恋の相手は選んだ主人公と異なる性別の12人から原作どおりランダムに決まります。人物シートは6枚×4人で、画像の変換・再描画はしていません。

共通99場面と活動分岐51場面、計150回の二択。11章と、創作・挑戦・探究・日常・寄り道・つながりの6系統を保持します。人物プロフィール、夢、各選択への返答、すべての結末本文を収録しています。

結末は人物24人×4種類と特別4種類の計100種類です。**100本の独立した長編ルートではありません。** 全人物独立の長編、表情差分、ボイス、オンライン同期は原作と同じく未実装です。音は原作の合成BGMと選択音です。

- 通常の両思い：好意65以上、信頼65以上、すれ違い42以下。最後の卒業選択で同じ街／別々の街が分かれます。
- 恋の途中：両思い条件には届かず、好意35以上、信頼45以上、すれ違い72未満。それ以外は片思いの結末です。
- 開始時8%で特別な縁のフラグが立ちます。この場合の両思い条件は好意80以上、信頼82以上、すれ違い22以下。原作の共通場面番号20・29・47・56・75・84（内部0始まり）で6回の追加のすれ違いが起きます。
- 特別結末はその両思い条件に加えて勇気80以上が必要です。最後の活動分岐で創作／挑戦／探究／その他の4種類になります。
- 「ツインレイ」は本作独自のフィクション設定です。現実の関係を診断する機能ではありません。相手の意思と自分自身の生活を尊重する原作の記述も保持しています。

## ブラウザで追加した機能

- ZatuPlayのブラウザ作品一覧へ戻るリンク、ブラウザ版表示、ローカルファイル参照へのバージョン付加。
- 自動保存、3つの手動保存枠、100結末の回収帳、旧版の結末記録、音設定、操作直前の復元用データを1件のJSONにまとめました。
- 返答画面の状態も保存します。再読込後に「つづきから」を選ぶと、未確認の返答を飛ばさず再表示します。最後の150回目の返答も「ふたりの結末へ」を押すまで残ります。
- 原作で選択後に表示していた保存成功文を改善しました。上部の保存状態と返答欄で、ブラウザに保存したか、このタブ内だけに記録したかを区別します。
- 新規開始、手動枠への保存、ロード、JSON復元、初期化、復元用バックアップへの巻き戻しには確認があります。実行直前の全データは、同じ原子的な保存の中で1世代の復元用バックアップとして残します。設定で書き出すか戻せます。
- 返答・場面・結末ボタンの重複入力、古い画面のボタン、読み込み中に画面移動したファイル、ロック待ち中に中断した操作は新しい状態を変更しません。
- メニュー、確認画面、別タブへの移動、非表示時にはBGMタイマーと発音を停止します。音声APIの非対応、生成失敗、再開拒否があっても音なしで遊べます。保存された音オン設定は、再読込後のポインター操作またはEnter／Spaceキーで音声の開始を試みます。キーを押し続けても繰り返し開始せず、メニュー表示中や非表示中には開始しません。

## 保存と失敗時の扱い

ブラウザ専用キーは `zatuplay.renai-sakusen.browser.v1`。自動書き込みはHTTPS等で利用できる Web Locks の排他ロック内で行い、最後に読んだ保存内容が変わっていないことを比較してから、`localStorage.setItem` を1回だけ行います。元APKの `renai-v1`、`renai-slot1`〜`3`、`renai-ends-v2`、`renai-ends` は自動で読み書きしません。

別タブとの競合、壊れたデータ、保存拒否、容量不足、Web Locks非対応時には既存データを上書きしません。失敗した操作そのものは反映せず、上部で通知します。その後は**このタブだけのメモリ保存**で続行でき、端末へ保存済みとは表示しません。メモリモードから自動で書き込みを再開することもありません。大切な記録は、タブを閉じる前に設定からJSONを書き出してください。設定の「保存領域の元データを書き出す」で、起動時／直前まで保持していた保存原文を救出できます。別タブの新しい保存を読むには、必要な書き出しを済ませてから再読込してください。

初期化はこのブラウザ版だけを対象にし、元APKのキーや他作品の保存には触れません。直前のバックアップを残すため、完全な消去ではなく復元可能な初期化です。次の置換操作はこの1世代バックアップも置き換えるので、複数世代を保管する場合はJSONを書き出してください。

## JSONの書き出し・読み込み

設定の「セーブを書き出す」で、進行中の状態、返答画面、3枠、現在と旧版の結末記録、音設定、1世代の復元用データを含む `zatuplay-renai-sakusen-backup-v1` 形式をダウンロードします。「ダウンロードを開始」と表示したあと、実際の保存先にファイルがあることを確認してください。

読み込みはUTF-8で2,000,000バイト以下のJSONを検査し、内容の確認後に実行します。思い出1件のJSON表現はUTF-8で1,024バイトまでです。原作の全返答・選択肢がこの範囲内に収まることを照合済みで、本文を切り詰めることはありません。過大な編集済みデータは取り込み前に拒否します。手動3枠と直前バックアップを含めた書き出し全体も同じ読込上限に収まるよう検証するため、正常に受け入れた記録から作るJSONは再読込できます。キャンセル、不正な入れ子や数値・ID・重複記録、読み込みエラー、書き込み失敗では全データを変更しません。名前や思い出の本文はHTMLとして実行せず、文字として表示します。同じファイルの再選択にも対応しています。

- ブラウザ版バックアップ：進行、3枠、音設定を復元し、現在の結末帳は統合して減らしません。上書き直前の全データを新しい復元用バックアップにします。
- 原作のv2状態、`renai-backup-v2`、v1状態、`renai-backup-v1`：明示的なファイル読み込みだけで移行します。手動3枠と音設定は現在のブラウザ版のものを残します。
- v1の99話の進行を、原作0.2.0と同じ対応で150枠の共通場面へ移します。能力値・名前・既存の思い出本文を保持し、旧思い出の選択番号もそのまま残します。旧版に存在しない分岐の履歴を捏造しません。99話完了は結末へ移します。
- 原作JSONには返答画面の情報がないため、保存されている次の場面から再開します。原作の最終到達状態は対応する結末を回収帳にも記録します。
- 原作の旧4結末は識別子が異なるため、100結末への置き換えはせず別の記録として保管・再書き出しします。

## 検証

`zatuplay-source/scripts/test-renai-sakusen.cjs` と `renai-sakusen-harness.cjs` は Node + linkedom によるDOM、Web Locks、保存、音声、ライフサイクルのモデル検証です。PNGの実デコードにはPythonのPillowを使います。

```sh
NODE_PATH=/tmp/rhythm-test-deps/node_modules:/tmp/riddle-test-deps/node_modules node zatuplay-source/scripts/test-renai-sakusen.cjs
```

- 原本から独立に生成した比較値で、21,600場面変種、192周・28,800選択の本文・返答・能力値・分岐・結末を照合。
- 通常／特別の閾値、100種類の構築状態からの分類、6回の特別なすれ違い、最終選択を検証。
- 通常のDOMボタンで150回選択して実際の結末処理まで到達し、返答途中・結末の再読込、3枠の復元、バックアップ、設定、旧版移行を検証。
- 破損、保存拒否、容量不足、Web Locks非対応、2タブの競合、取消／遅延読み込み／ロック待ち／重複操作／音声失敗を検証。
- 画像と物語の原本ハッシュ、配布全ファイルのハッシュ、公開側ミラーのバイト一致を検証。

これらは公開Chromeでの実プレイの代わりではありません。100結末がすべて通常プレイで到達可能と証明したものでもありません。公開環境でのChrome、狭い画面、実ダウンロードと再読込、音の聴取は別途CUAで確認する必要があります。

## 公開Chromeで1周するための通常UI手順

1. 「新しい恋をはじめる」から主人公を選び、呼び名を入力。「この主人公ではじめる」→「確認して実行」。この時点で相手はランダムに決まります。
2. 画面の「選択 1 / 150」を確認し、AかBを押して返答を読む。最も単純な確認用なら常にAを選んでも、150回で必ず何らかの結末へ到達します。望む結末を保証する手順ではありません。
3. 「次の場面へ」を押す。以後、選択と返答確認を繰り返します。共通99場面と分岐51場面が表示されます。途中でプロフィール、活動分岐、思い出帳を確認して閉じても進行は増えません。
4. 任意の返答画面で再読込し、タイトルの「つづきから」で同じ返答に戻ることを確認。手動枠1〜3にも場面／返答を保存してロードを確認します。
5. 150回目は「次の場面へ」が「ふたりの結末へ」に変わります。押すと結末本文と回収数が表示されます。「100の結末図鑑」→「回収済み」で1件増えたことを確認してください。同じ結末の再表示では増えません。
6. 設定から全JSONを実際にダウンロード。進めた後に同じファイルを読み込み、キャンセルでは変わらず、確認すれば復元されること、同じファイルを2回選べることを確認します。
7. 別タブで同じ作品を開いて双方から進め、一方が「このタブ内だけ」と表示され、先に保存したタブの記録が上書きされないことを確認。必要なデータはそれぞれJSONを書き出します。
8. 音をオン／オフにし、メニュー、別タブ、非表示で止まることを聴取。ZatuPlayへ戻るリンクでブラウザ作品一覧に戻ることを確認します。
