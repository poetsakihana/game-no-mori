# 咲華 SKHN Music — 1.0-web.1

Faithful local browser utility, collection 19. Not a game, streaming service, or empty mock player. Original UI, title search, genre/comma-separated playlists, metadata editor, previous/next over the filtered list, nonzero-offset shuffle and single-track repeat are retained. Seven native methods are implemented by `backend.mjs`: pick / play / toggle / seek / state / list / edit. The 700 ms UI polling and nonpersistent playback state are retained. No songs are bundled for ordinary use; `qa-fixtures` contains only newly synthesized owned test tones, never automatically imported or substituted for user files.

## Provenance

Original APK label 咲華 SKHN Music, package `jp.sakihana.skhn`, version 1.0 / code 1; 33,301 bytes; SHA-256 `dbac8a684f780faafb5aad2568f6f8f3256fcac0ca18b083975e7dcab933eaba`.
Original `assets/index.html`: 7,674 bytes. UI is adapted from that source. Backend is a new browser implementation derived from read-only DEX disassembly and decompiler aid (not treated as compilable Java). Native framing/import/playback/catalog semantics were checked against the original. No APK, DEX, SDK, signing material, external fonts or vendor code is published here. Native source does not declare device permissions or bundle songs. This is provenance documentation, not an independent copyright audit.

## Data and limits

SKHN = ASCII `SKHN0001`, LE32 JSON byte length, UTF-8 header, unchanged audio. Header 1–1,048,576 bytes; version 1; string title and SHA-256 required; nonempty payload with matching lowercase SHA-256. Raw filename stem is title, artist 咲華, original filename and native MIME mapping are preserved. Identity is SHA-256 of audio only, not filename/title. Imported SKHN container bytes and raw payload are retained exactly. Raw audio is losslessly wrapped. Genre defaults 未分類; playlists empty.

Browser-specific safety limits: 64 MiB audio/track (native limit was 512 MiB), 128 MiB selected input, 256 MiB audio/library. ZIP ≤64 MiB, ≤256 entries, ≤128 MiB expanded, ratio ≤200; stored/Deflate only, no encryption, split ZIP or ZIP64. Central/local records, bounds, overlap and CRC are checked; inflation is streamed with a declared-size hard stop. Names are inert labels, never filesystem paths or network requests. Nested archives/unsupported suffixes are skipped. Structurally invalid/CRC-broken archives fail as a whole before any archive entries are saved, a deliberately stricter browser behavior than native per-entry import. Earlier completed files in the selection remain saved. UTF-8 ZIP names supported; non-UTF8 legacy names may display imperfectly. Deflate requires browser `DecompressionStream('deflate-raw')`; unsupported browsers receive an explicit extract-first message.

IndexedDB `zatuplay-skhn-music-web-v1` has catalog/media stores. Deduplication, quota accounting and Blob + metadata insertion share one readwrite transaction, serialized across tabs. Failure rolls both stores back. Metadata uses revision compare-and-set, preventing silent concurrent edits. Corrupt catalogs are reported, never reset automatically. BroadcastChannel/focus refresh covers other tabs. Browser quota, eviction and private browsing differ from Android; retain originals. No delete/reset feature is added. Per-track SKHN/audio downloads are non-destructive backups; genre/playlists are NOT included. Browser data is separate from Android files. No account, upload, credentials, arbitrary file read or remote media fetch.

The real HTMLMediaElement receives only imported Blob bytes. Each selection has its own generation, element and Blob URL; replaced players are paused/released, stale callbacks ignored. Decode and autoplay failures are visible; original bytes remain saved. Codec support differs from Android. Leaving cancels pending imports at the next safe boundary, releases playback, and preserves already committed tracks. File-picker cancellation changes no storage, and input is reset for same-file reselection. This page does not install an offline service worker; after page assets load, media work is local. Offline reload depends on browser/site caching and is not promised.

## Tests and fixture preparation

From `zatuplay-source`: `node scripts/test-skhn-music.mjs` tests parser, ZIP bounds/CRC/deflate, byte preservation, SHA identity, selection/shuffle and player generation cleanup. It regenerates owned 6/7-second mono PCM WAV fixtures, matching SKHN, duplicate/new/unsupported ZIP, and invalid-hash SKHN. These are audible test tones; use moderate volume.

Optional IndexedDB API model tests use `fake-indexeddb@6.2.4` from the official npm registry in an external temporary test directory, not a runtime dependency. Run with `SKHN_IDB_MODULE=/path/to/fake-indexeddb/build/esm/index.js node scripts/test-skhn-music.mjs`. Tests cover simultaneous duplicate inserts, revision conflicts, abort rollback and corrupt catalogs. This does not prove real browser quota, file picker or playback behavior.

DOM/backend model coverage: install `jsdom@26.1.0` in the same temporary test directory and run `SKHN_JSDOM_MODULE=/path/to/jsdom/lib/api.js SKHN_IDB_MODULE=/path/to/fake-indexeddb/build/esm/index.js node scripts/test-skhn-music-ui.mjs`. Four groups exercise real adapter code with modeled DOM/storage: import/reselection/cancel/ZIP counts, filtering and edit/cancel, mode toggles and invalid imports, and interrupted import preservation. These are not actual browser/file-picker tests.

`node scripts/sync-skhn-music.cjs` mirrors only this utility and generates SHA-256 manifest. No shared catalogs or registration are changed. See `QA.md` for the separate actual-browser acceptance gate. Source checks passing do not mean real audio playback or audible audition was performed.
