# 揚げどき！フライバトル ブラウザ版

元APK **1.0** → **1.0-web.2**。ZatuPlay `collection-07`。

原APKのAndroid Canvasゲームを、原本の描画座標・ルール・音源を基にCanvas2Dへ移植しています。別のミニゲームへの置き換えではありません。全100面、4人のライバル、4種類の食材、45秒対戦、端末内TOP10を収録しています。

## 遊び方

- 「はじめる」→「ストーリー 全100面」→「STAGE 1」。
- 左から **1・2・3・4キー**、または食材のタップ・クリックですくいます。
- 表示が100％に近いほど高精度。95〜105％付近を狙い、4つの槽を順に見てください。165％を超えると自動的に焦げて精度0になります。
- 45秒後、1個以上調理しており、あなたの累積精度がCPUより高ければ勝利。同点は負けです。平均精度での比較と同じ結果になります。
- 最新の解放面で勝つと次の面が開きます。25面ごとにライバルが変わり、100面で優勝です。
- P / Escapeで一時停止、Mで音の切替。Tabで項目を選び、Enter / Spaceでも決定できます。スマートフォンは横向きを推奨します。

## 原作から保持した内容

- タイトル、100面の選択（20面×5ページ）、対戦、一時停止、勝敗結果、再挑戦、次面、TOP10、料理人の名前変更。
- 1000×650の座標、色、食材の形・衣の粒・油の泡・湯気、すくうアニメーション、進捗率・ゲージ。
- 食材はコロッケ、エビフライ、からあげ、天ぷら。ライバルは見習い コムギ、屋台 アゲ丸、料理長 カリナ、揚げ物王 サクゾウ。
- 揚げ時間 `(4 + random × 3) / (1 + (stage − 1) × 0.015)` 秒。
- 精度 `round(max(0, 1 − 2 × abs(age / target − 1)) × 100)`。点数は精度×10。
- 1個処理するごとのCPU精度 `(0.38 + random × 0.34 + (stage − 1) × 0.002) × 100`。
- Java `Random` の48ビットLCG、24ビット `nextFloat()`、`nextInt(4)`、乱数を消費する順序。目標時間・精度・CPUはDalvikのfloat32演算順序を再現しています。
- 原WAVをそのまま使用。BGMループ・音量0.24、すくう音0.65、精度90以上は再生速度1.4倍、それ以外は1倍。
- 得点降順のTOP10。同点は登録順。負けた対戦も原作と同じく登録されます。

## ブラウザ向けの変更と保存

原作の保存対象は解放面・名前・TOP10のみです。ブラウザ版では音設定、BEST、画面・途中の対戦・食材・経過時間・乱数状態・アニメーションも追加保存します。APKや別端末と同期しません。保存キーは専用の `zatuplay.fly-battle.web.v1` です。

- ブラウザの音の制限に合わせ、最初の「はじめる」操作後に音を開始します。音APIや音源の読み込みに失敗しても無音でプレイできます。
- 原作は描画フレームごとに最大0.05秒を加算します。ブラウザ版は120Hzの固定ステップで進め、入力直前にも時計を更新します。FPSによって勝負の速度が変わらないようにした変更です。45秒は5400ステップ。元のフレーム依存のfloat32累積時間とは微小な差があります。
- 250msを超える処理停止、画面の非表示、フォーカス離脱、再読込後は一時停止。勝手に時間を進めず、明示的な「再開」で続けます。原作の復帰時自動再開とは異なります。
- 同じ食材への120ms以内の重複操作、対戦開始直後180msの誤操作、キーリピートを無視します。最短の揚げ時間より十分短く、新しい食材を誤って連続ですくうことを防ぎます。ポインタは原作と同じく押した時点で反応します。
- ブラウザの暗号学的乱数で48ビット初期シードを作ります。非対応時のみ時刻を使います。Androidの無引数Randomの初期シードそのものとは異なり、保存したシードから先の系列は継続します。
- Web Locksで保存の書き手を1画面に限定します。非対応時は読み込み・メモリ内プレイ・JSON書き出しのみで、保存先へ一切書き込みません。不確実な比較だけで書き込む代替は使いません。
- 保存拒否・破損・外部変更を検出したら上書きを止めます。現在の進行は「記録を書き出す」、読めない元記録は保護画面の「保存済み記録を書き出す」で保管できます。「保存せずに遊ぶ」では元記録を変えません。
- JSON読み込みには検証と確認を設け、上書き前の記録を `.before-import` に保存します。バックアップ作成が失敗した場合は復元しません。リセット・記録消去ボタンは設けていません。
- 通常の保存は約0.5秒ごとと操作・停止・対戦終了時。OSによる強制終了等では最後に保存した直後まで戻る可能性があります。サイトデータを消す前にJSONを書き出してください。
- キーボード操作、安定したDOMボタンと食材の進捗率、読み上げ用の戦況、全画面、一覧へ戻るリンクを追加しています。公開のチート・状態注入・テスト専用窓はありません。

## 自動検証

リポジトリの `zatuplay-source/scripts/test-fly-battle.cjs` をNodeで実行します。試験用のDOMモデルにlinkedom、実際のCanvas2D描画に `@napi-rs/canvas` を使用し、製品ファイルには組み込みません。

検証内容:

1. 原DEX・WAVのハッシュ、ソース側と公開側の全ファイル一致。
2. 独立実装したJava乱数と4種のシード×1,000組の値を比較。DEXのfloat32定数をビット列から復元して照合。
3. 全100面の難度式・目標時間・食材順・CPU・精度境界を独立参照計算と比較。
4. 得点や解放状態を注入せず、初期状態から通常ルールで100面連続勝利。100×45秒をモデル上で進行。
5. 焦げ、空結果、同点負け、解放制限、終了重複防止、TOP10、フレームレート差、途中乱数復元。
6. 実Canvas描画とDOM操作でタイトル・名前・5ページ・ランキング・1面の勝利と保存再読込。
7. 解放済みの境界試験データを使い、25・26・50・51・75・76・99・100面を通常のDOMポインタ／キー入力と画面の進捗率だけで勝利。対戦中の内部状態注入は行いません。
8. 一時停止、非表示、フォーカス離脱、処理停止、再読込、ポインタ重複、キーリピート、別タブ競合、Web Locks非対応、破損、保存拒否、外部変更、JSON復元・キャンセル・元記録保全・非同期読込の順序逆転（最後に選んだファイルのみ採用）。
9. 音量・速度・ミュート保存、音APIなし・再生拒否、外部実行依存やデバッグ用状態注入APIがないこと。

**検証範囲の区別:** ルール・DOM・時計・音APIは自動検証用モデルで、描画は実Canvas2Dです。生成したPNGは目視確認しています。実Chromeでの確認は以下の別工程です。自動検証の全100面完走は、人手による全100面完走を意味しません。

Androidとブラウザではフォント・文字幅・アンチエイリアス・音の混合処理が異なるため、ピクセルや音声出力の完全一致は保証しません。

## 1.0-web.2の修正

公開Chromeの確認で、復元を取り消したあとも確認待ちの案内が残る表示を発見したため、ボタン取消とEscape取消の両方で「復元をキャンセルしました。記録の置き換えは行っていません。」へ更新するよう修正しました。記録は置き換えません。取消後の状態保全・案内・同一ファイル再選択を回帰テストに追加しています。

CSS、core.js、render.js、app.jsの読み込みURLへ `?v=1.0-web.2` を付け、以前の資産キャッシュが混在しないようにしました。原APK・DEX・WAV・ルール・保存形式と保存キーは変更していません。上記の初回実Chrome確認は修正前の1.0-web.1に対する結果です。1.0-web.2は全18群の自動検証と独立再検査を通過し、以下のとおり公開後の実Chrome再確認も完了しています。
