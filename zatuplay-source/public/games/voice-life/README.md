# Voice Life 7.0-web.1

Collection 21, local-only browser adaptation of **Voice Life 7.0 / code 7** (`jp.sakihana.voicelife`). This is the original fictional livestream-life simulation, not a real broadcasting service, messaging service, microphone recognition system, or paid-currency product. CPUs do not hear or understand microphone audio. Coins cannot be purchased or cashed out.

**Status:** local implementation and author/model tests complete. Actual Chrome UI, real file chooser/download, real two-tab lock behavior, microphone hardware, mobile devices, Safari/Firefox and offline reload have **not** been verified by this implementation task. No microphone permission was requested. No publication, catalog change, upload or commit was performed by this task. Follow `QA.md` before changing that status.

## Deliberate browser changes

1. **Isolated atomic persistence.** Only `zatuplay.voice-life.web.v1` is accessed. Native keys `voice-life-v1`, `voice-life-v4`, `voice-life-media-v7`, `voice-life-social-v7` are never read, migrated, removed or written. A complete account/rewards/family/media/social payload is stored in one localStorage write, batching synchronous source saves in a microtask. The browser owns an exclusive Web Lock for the page lifetime and compares the exact original storage record before each write/replacement. A second tab or a browser without Web Locks reads a snapshot but stays memory-only. Closing the other tab does not silently acquire ownership; reload the desired tab. This does not claim protection from hostile same-origin code outside this app.
2. **Honest save failure.** Status distinguishes pending, durably saved, memory-only, conflict, corruption, denied storage and quota failure. Failures preserve previous bytes and current memory. No automatic corruption repair or resetting. Explicit Retry cannot overwrite unreadable/corrupt originals. A raw-original download is provided. A conflict is not resolved by last-writer-wins; export the memory state, close competing tabs, then reload/review.
3. **Complete JSON backups and recoverable replacement.** Browser JSON format/version plus all four payloads are required; unknown/missing fields, invalid IDs, enums, integers, dates, URLs, images, duplicate follow IDs and over-limit collections are rejected. Files are bounded to 4 MiB before reading. Imports decode accepted local JPEG data before confirmation. Canceled/stale reads do nothing. Confirmed import/reset retains one generation of the previous memory state **and** the prior durable raw record, including corrupt raw bytes. “置換前に戻す” restores that memory state, and “置換前原本を書き出す” exports the previous raw record. Older recovery generations are intentionally replaced by the next confirmed replacement. If the atomic recovery write cannot fit, nothing is replaced. Standard backups omit recovery history; raw-original files are diagnostic/recovery copies, not accepted as standard backups.
4. **Lifecycle and settlement.** A running stream is still session-only, not a resumable durable broadcast. Unlike the APK source, a normal tab/section departure, hidden document, return to the catalog, mode change or pagehide synchronously stops microphone capture and settles the current session exactly once. This prevents hidden timer progress. Abrupt process/device termination can still lose uncommitted session points; already saved affinity/social/family effects remain as in the source. No resume/double-settlement claim is made. Co-host state is cleared when streams end and on load/import.
5. **Race fixes.** CPU replies and room replies have generation/identity checks. Pending microphone starts can be canceled; late streams have all tracks stopped, and repeated start/end cannot settle twice. Reset also stops pending/active capture. Image operations have per-slot generations, cancellation, object-URL release and a 30-second processing deadline; older picks cannot undo newer picks/removal, navigation, reset or import. Import/restore reads reject newer saves and canceled/navigation operations.
6. **Honest daily rewards.** The source labels today's board as yesterday when it detects a date change. This port instead saves the actual last observed rank/points/time for a JST day and uses that observation at rollover. UI shows the observation time. It is **not an exact midnight historical snapshot**, and skipped/unobserved days are not invented. Reward tiers are unchanged and claims are atomic/once-only for the stored ledger. CPU score formula, including its original UTC-minute cycle combined with a JST day seed, is unchanged.
7. **Stable follow identity.** Original follows use display names and unintentionally merge same-name hosts. Browser follows use `h:<id>` or `p:<id>`; names/generators remain unchanged. Since native saves are intentionally not imported, there is no fabricated name-to-ID migration.
8. **Safe local images/profile.** File selection supports JPEG/PNG/WebP, maximum **15 MiB**, 40 million advertised/decoded pixels and 16,384 per axis; image format/signature/dimensions are checked before decode. Original aspect-preserving JPEG `.75` downscale caps remain **320×320 avatar / 1000×450 banner**. Other image types, especially SVG, are deliberately rejected. Saved/imported images must be bounded JPEG data URLs with matching headers/dimensions and successful decode; remote image URLs are rejected. Profile links must be plain HTTPS without credentials/control characters and are not automatically opened/fetched. Input is rendered as text. CSP denies network connections, remote images, objects, forms and arbitrary scripts.
9. **Browser controls and limits.** Direct `../../browser/` return; keyboard-accessible standard buttons, visible focus, responsive navigation/media controls, Escape closes CPU profile/cancels pending microphone start, reduced-motion gift effects and version/content-hashed assets. Backup limits: counters ≤10^12, 1,200 relationships/CPU social IDs, 1,700 combined follow IDs, 20 histories, 60 family-chat entries, 3,650 reward snapshots/badges, bounded strings and JPEG data. Limits fail closed rather than silently truncating an imported save. The original family-chat display bound is now also enforced at insertion. There is no service worker: a fully loaded page needs no network, but offline launch/reload is not guaranteed.

## Reproduce the local checks

From `zatuplay-source/`:

```sh
python3 scripts/generate-voice-life.py
node --check public/games/voice-life/app.js
node --check public/games/voice-life/storage.js
NODE_PATH=/tmp/riddle-test-deps/node_modules:/tmp/rhythm-test-deps/node_modules node scripts/test-voice-life.cjs
python3 scripts/verify-voice-life.py
```

Author harness dependencies: Node.js, `linkedom`, `@napi-rs/canvas`. The supplied environment already had these in the paths above. On another computer, install those packages through a normal approved package-manager workflow or provide `NODE_PATH`. Python checks use only the standard library. Do not run the original fixture as an actual website, since it intentionally retains source defects and original storage keys.

The test harness compares full original generators and source-derived behavior, not shortened replacement content. It uses a modeled DOM/storage/timers/permission API and an actual local raster codec. Cached identical Intl queries limit test memory without altering returned date/time values. It does **not** launch a browser or call a real microphone. Exact report, file hashes and mirror verification are recorded in the dedicated `scripts/voice-life-*` artifacts. See `QA.md` for the separate ordinary-UI acceptance recipe.
