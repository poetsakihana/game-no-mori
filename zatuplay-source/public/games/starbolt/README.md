# スターボルト：8つの機械要塞

ブラウザ版 **1.0-web.1**。Android版 **1.0 / versionCode 1**（`jp.sakihana.starbolt`）に含まれる、全8要塞のゲームを移植しています。ブラウザ版にだけ追加した安全対策と検証範囲を以下に明記します。

## 原作の内容を維持

- 全8要塞は最初から自由選択。溶鉱炉、氷の研究所、森林工場、発電塔、水路基地、採掘場、天空回廊、夜の都市。原作の8ボス名・色・演出・エンディング全文を収録。
- 各ステージ幅4,800。原作の式から生成する17床（地面含む）、11敵、4トゲ。床の座標・幅、敵の種類・移動・射撃、ボスの動き・扇状弾を維持。原作に無いマップや敵を補っていません。
- HP28、ボスHP48。敵・トゲ3、ボス接触4、敵弾2ダメージ。被弾後80ティック無敵。通常敵撃破でHP1回復（最大28）。60 Hz固定シミュレーション。
- 通常弾＋8ボス武器。リーフ3方向、岩石は速度6・通常敵ダメージ3、風は8ティック間隔（他17）、影は通常敵を貫通。その他の弾速10。ボス弱点は前の色の武器、最初のボスは影。弱点4、その他1ダメージ。火炎・氷結・電撃・水流に原作にない状態異常は追加していません。
- x > 3,850でボス前チェックポイント。同じ挑戦で敗北後の再挑戦はx=3,890・HP28。新しいステージ選択ではリセット。最後の8体目で原作の結末を表示します。
- ←→ / A D、Space、Z、X、P、および画面ボタン。絵は原作同様のCanvas 2Dによる図形描画。効果音は短いsquare波で、音楽・外部素材・通信APIはありません。

## ブラウザ版の追加・修正

- 元の `starbolt-v1` は一切読み書きしません。専用 `zatuplay:starbolt:1` だけを使用。自動保存対象は撃破済みボスと追加した音ON/OFF。途中のHP、位置、武器、弾、チェックポイント、選択中ステージは保存しません。原作も途中状態は保存しません。
- 元の保存は撃破ID配列のみ。ブラウザ版では重複なし0～7の整数配列、音boolean、スキーマ、単調な改訂番号を検証します。JSON書出・読込・記録リセットはブラウザ版追加機能です。バックアップには撃破記録と音設定をすべて含め、途中状態は含めません。
- Web Locksの排他ロック内で元の保存文字列を比較してから書込み。別タブと競合したら一時停止し、古いタブは上書きしません。Web Locksが無い場合は読み取りだけ、記録更新はこのページのメモリ内です。
- 保存拒否・容量不足・不正データは画面に明示。不正な既存データを削除・上書きせず、一時プレイに切替。自動マイグレーションも他作品のキー列挙もしません。バックアップで一時記録を退避できます。
- 読込は最大4,096 UTF-8バイト、正しい形式・版・既知項目のみ。重複キー、不正型、過深ネスト、範囲外ID、重複ID、余分な項目は拒否。保存処理中は一覧への移動を止め、保存完了後の再操作を案内します。読込・リセット前に現在記録の復旧用バックアップをダウンロードし、保存先確認と明示確認を求めます。ブラウザのダウンロード完了そのものは検知できないので、成功したと断定しません。
- ファイル選択・読込のキャンセル、同じファイルの再選択、古い読込Promiseの遅延完了を分離。設定を閉じた後の読み込みは適用しません。
- フォーカス喪失・非表示・ページ離脱・設定表示で入力解除＋一時停止。明示的に再開するまで進まず、経過時間の追い付きもありません。250 msを超えるフレーム停止でも手動再開に切替。通常のフレームでは原作同様、最大80 msを固定60 Hzで処理。
- ポインターキャンセル・キャプチャ喪失、複数ポインター、Aと左矢印など複数の同方向キーを処理。中断前の長押しキーのrepeatでは入力を復活させません。設定内の操作をゲームへ送らず、Spaceでボタン操作中に跳びません。
- 音声APIの未対応・resume拒否・再生失敗でゲームを停止しません。音をONにし直すと再試行可能。音声の可聴性は実機確認が必要です。
- ステージ選択へ戻る操作は途中状態の消失を確認。カタログへは同一タブの `../../browser/` に直接戻ります。Canvasの縦横比維持、狭い画面でスクロールできる選択画面、通常のページズームを許可しています。

### 原作の問題を再現して修正した箇所

1. 一時停止後に別ステージを開始すると、原作は右上のボタンに「再開」が残ります。ブラウザ版はゲーム状態から毎回表示を決めます。
2. 原作は致死ダメージでresultになっても同じstepの処理を続行。敵撃破によるHP回復や、死亡後の敵・弾処理が発生し得ます。ブラウザ版は致死ダメージ直後にstepを終了し、勝敗が上書きされないようにします。
3. 原作の通常敵への弾ダメージ・貫通判定と弾色は発射後の「現在の武器」を参照し、ボスだけ発射時の武器を参照していました。すべて発射時の弾に保存された武器を使用します。岩石を撃って通常弾へ切り替えても、飛んでいる岩石はダメージ3です。影の貫通も維持します。
4. ステージ開始時に原作は直前のカメラ位置を最初のstepまで残します。ブラウザ版は開始位置に戻し、1フレームの別地域表示を避けます。被弾でHPが0未満になっても、HPバーを負の幅で描きません。

難度、移動速度、ジャンプ、敵密度、射撃タイミング、ボスHP、武器取得条件を変更していません。

## 自動検証

リポジトリルートから、`node zatuplay-source/scripts/sync-starbolt.cjs --check` と `NODE_PATH=/tmp/riddle-test-deps/node_modules:/tmp/rhythm-test-deps/node_modules node zatuplay-source/scripts/test-starbolt.cjs` を実行します。テスト依存は `linkedom` と `@napi-rs/canvas`。通常のブラウザ配信には依存不要です。

原本engine.jsを独立VMでそのまま実行する比較オラクルを使い、全8ステージを通常の移動・射撃・実際に獲得した武器だけでクリアする軌跡を毎ティック比較します。HP・クリア・敵HPを注入しないモデルキャンペーンは全8体撃破・エンディングまで完了。別途、境界値・ダメージ・武器・チェックポイント・致死処理等の単体テストでは明示的なfixtureを使います。

著者テスト25グループが通過。DOMモデルでの実操作イベントから最初の要塞を通常クリアし、別の境界fixtureではボス前からの再挑戦・8体目の撃破・原作エンディング全文を確認。Canvasの実ラスタ描画、保存失敗・競合、読込キャンセル・同一ファイル・非表示やフォーカス喪失後の遅延完了なども検証しました。**これらはChromeでの人手プレイ、実機タッチ、CSSレイアウト、効果音の試聴、公開URLの検証ではありません。**

## 再検証用の実Chrome QA手順

以下は今後も使える網羅的な手順です。今回実際に完了した範囲は次節に分けて記載し、全項目実施済みとはしません。

1. HTTPで `zatuplay/games/starbolt/` を開く。タイトル、全8選択肢、保存表示、Consoleエラー無し、Networkに外部リソース要求無しを確認。
2. 960px以上・390px・320px幅、縦横画面で選択メニューをスクロール。全8要塞へ入り、元の床・敵・トゲ・色・各ボス表示を確認。16:9の実画面が伸びないこと、ボタンが重ならないことを確認。
3. キーボードと画面ボタンで移動・ジャンプ・長押し射撃、X武器・P停止。左右複数キー、同時タッチ、範囲外で離す、長押し中にタブ切替・別窓・設定・戻る、repeatキーが再開後に復活しないこと。
4. 溶鉱炉はまず通常の右移動＋Zで進み、ボス部屋x約3,970で右を離して射撃を続ける。少なくとも1つの全道中＋ボスを通常操作で倒し、火炎弾取得・選択の✓・再読込後の記録を確認。2つ目のボスで獲得武器を使用。全8体の実プレイを行っていない場合は「全8体の手動クリア」と報告しない。
5. ボス前まで進み、実際に敗北→再挑戦でチェックポイントと満タンHPを確認。停止→選択→別ステージで「一時停止」表示になること。途中状態はリロードすると保存されないこと。
6. 音ON・OFF・再読込・初回ジェスチャー後の効果音を実際に聴く。無音環境・拒否時はプレイ継続と表示を確認。
7. JSONバックアップを実ダウンロード。キャンセル、同ファイル2回、読込中閉じる・キャンセル・新しい読込、4 KB超、他ゲーム、重複キー、不正型の拒否を確認。リセットをキャンセルし、実行後に復旧用バックアップで戻す。
8. 同一オリジンの別タブを開き、音設定などを一方で保存。古いタブの競合表示・停止・上書き禁止を確認。保存拒否・容量不足・不正記録は隔離テスト環境で確認し、通常記録を壊さない。
9. 実際の `../../browser/` 戻り先、同一タブ、公開ファイルのバージョン付き参照、HTTP 200、MIME、公開コミット一致を確認。
